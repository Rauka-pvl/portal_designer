## Раздел 1. Резюме для владельца / Executive summary

**Итоговый статус: Не соответствует**  
*(RU)* По подтверждённым в исходном коде и конфигурации фактам сайт как оператор персональных данных не выполняет базовые обязанности Закона РК «О персональных данных и их защите» (согласие, назначение ответственного, журналирование действий с ПДн, криптозащита чувствительных полей, права субъекта).  
*(ENG)* Confirmed in source/config: the site does not meet baseline PD Law duties (consent, DPO appointment evidence, PD action logging, crypto for sensitive fields, data-subject rights). Production hosting location and backups were **not** verifiable from this workstation.

| Метрика | Значение |
|---------|----------|
| Общий уровень риска | **Высокий** |
| Critical | 3 |
| High | 11 |
| Medium | 8 |
| Low / Info | 5 |
| Подтверждённые нарушения законодательства (по коду/организации) | **≥ 9** |
| Можно ли выпускать в production | **Нет**, до устранения Critical/High юридических и организационных пробелов и подтверждения локализации в РК |

**Наиболее опасные проблемы**
1. Регистрация и формы собирают ПДн **без** отдельного согласия и без политики конфиденциальности.
2. Чувствительные данные (ИНН/БИН, банковские реквизиты, адреса клиентов/объектов) хранятся **в открытом виде** в БД; нет доказательств соответствия СТ РК 1073-2007.
3. Нет доказательного журнала действий с ПДн (просмотр/изменение/выгрузка/удаление) по Правилам № 179/НҚ.
4. Нет механизмов прав субъекта (экспорт, полное удаление, отзыв согласия) и оргдокументов (ответственный, инциденты).
5. Production-сервер, backup, TLS, firewall — **не проверены** (среда local).

**Немедленно**
- Не выводить текущую сборку в production с реальными клиентскими данными.
- Ввести согласие + политику; прекратить приём полного PAN/CVC в приложении; зашифровать/минимизировать банковские и идентификационные поля; назначить ответственного; зафиксировать страну размещения БД/backup.

## Раздел 5. Карта потоков данных

```
Субъект (дизайнер/поставщик/клиент данные)
  → Browser (Blade/JS, CDN fonts/libs: bunny.net, jsdelivr, unpkg)
    → Laravel HTTP (web/api, CSRF web, Sanctum API)
      → MySQL (ПДн в открытом виде; sessions; queues database)
      → storage/app/public (файлы; URL /storage/…)
      → storage/logs/laravel.log (риск попадания ПДн при DEBUG)
      → MAIL_* SMTP (пароли сброса, уведомления)
      → (опционально) AWS S3 при заполнении AWS_* (region default us-east-1)
      → ActivityEvent (CRM-лента, не полный аудит доступа к ПДн)
      → Резервные копии / prod ЦОД / Redis prod — НЕ ПРОВЕРЕНО
```

Внешние передачи, подтверждённые в коде:
- **fonts.bunny.net**, **cdn.jsdelivr.net**, **unpkg.com** — загрузка статики (IP/User-Agent браузера; обычно не содержимое форм, но трансграничный сетевой контакт).
- **SMTP** (`MAIL_HOST` задан в `.env`) — email с ПДн возможны.
- Поля **telegram/whatsapp** — идентификаторы мессенджеров в БД; прямая API-отправка в Telegram/WhatsApp из кода не подтверждена как обязательный поток.

## Раздел 7. Подробное описание нарушений (ключевые)

### KZ-01 — Отсутствие согласия при регистрации

- **Критичность:** Critical  
- **Тип:** Юридическое нарушение  
- **Статус:** Подтверждено  
- **Компонент:** `resources/views/auth/register.blade.php` (форма name/email/password без checkbox согласия)  
- **Описание:** Сбор ПДн начинается без отдельного согласия, без указания оператора, целей, срока, передачи третьим лицам, трансграничной передачи, способа отзыва.  
- **Доказательство:** В форме только CSRF + поля учётки (стр. 58–117); поиск по репозиторию `согласи|персональн|privacy|consent` — политика/UI согласия не найдены.  
- **Сценарий риска:** Незаконная обработка; невозможность доказать законность; претензии субъектов и уполномоченного органа.  
- **Данные:** name, email, password (+ далее телефон и др.).  
- **Норма:** Закон 94-V ст. 8; [Әділет Z1300000094](https://adilet.zan.kz/rus/docs/Z1300000094).  
- **Почему применимо:** Сайт — оператор ПДн частных пользователей.  
- **Рекомендация:** Checkbox (не pre-checked), ссылка на актуальную политику, фиксация версии текста, timestamp, IP, user-agent; журнал согласий.  
- **Приоритет:** Немедленно / до production  
- **Сложность:** Средняя  
- **Retest:** Регистрация без согласия отклоняется; в БД есть запись согласия с версией.

### KZ-02 — Нет политики конфиденциальности и версии согласия

- **Критичность:** Critical · **Тип:** Юридическое / орг. · **Статус:** Подтверждено  
- **Доказательство:** Glob `privacy*|consent*|политика*` — 0 файлов; нет маршрутов privacy.  
- **Норма:** 94-V ст. 8 (содержание согласия).  
- **Рекомендация:** Опубликовать политику (оператор, БИН, категории, цели, сроки, третьи лица, трансграничная передача, контакты ответственного); versioning.

### KZ-03 — Ответственное лицо не назначено (нет доказательств)

- **Критичность:** High · **Тип:** Орг./юридическое · **Статус:** Подтверждено как отсутствие артефактов  
- **Норма:** 94-V ст. 25 п. 2 подп. 10) — для юридических лиц.  
- **Условие:** Если оператор — юрлицо, обязанность обязательна.  
- **Рекомендация:** Приказ о назначении; контакты на сайте/в политике.

### KZ-04 — Права субъекта не реализованы

- **Критичность:** High · **Статус:** Подтверждено  
- **Доказательство:** Нет маршрутов export/delete-account/withdraw-consent; SoftDeletes оставляют данные.  
- **Норма:** 94-V ст. 24.  
- **Рекомендация:** Self-service или регламент ≤ установленных сроков; процедура hard-delete + очистка файлов/токенов/очередей; учёт backup.

### KZ-05 — Журналирование действий с ПДн отсутствует

- **Критичность:** High · **Статус:** Подтверждено  
- **Компонент:** `ActivityEvent` / `ActivityFeedService` — CRM-события (`event_type`, `body`, `meta`), не аудит доступа к ПДн.  
- **Норма:** 179/НҚ п. 7 подп. 4)–5); 94-V ст. 22.  
- **Рекомендация:** Immutable audit log: actor, action, entity, fields (masked), IP, outcome; отдельно от product feed; защита от изменения.

### KZ-06 — Нет подтверждённой криптозащиты хранения чувствительных ПДн

- **Критичность:** Critical · **Статус:** Подтверждено  
- **Доказательство:** Поля `suppliers.inn`, `bin`, `checking_account`, `bik`, адреса клиентов/объектов — обычные string/text без encrypt casts; Laravel `Crypt` используется точечно для temporary password. Нет сертификатов СКЗИ / СТ РК 1073.  
- **Норма:** 179/НҚ п. 8–9; СТ РК 1073-2007.  
- **Почему применимо:** При квалификации данных как ограниченного доступа — прямо; даже без неё ст. 22 требует меры защиты.  
- **Рекомендация:** Минимизация; field-level encryption сертифицированным СКЗИ или вынос в контур с подтверждённой защитой; TLS к БД; не полагаться только на AES в OpenSSL Laravel.

### KZ-07 — Локализация в Казахстане не подтверждена

- **Критичность:** High · **Статус:** Требуется дополнительная проверка  
- **Доказательство:** Проверена только local MySQL на рабочей станции Windows; конфигов Nginx/ЦОД в репозитории нет.  
- **Норма:** 179/НҚ п. 9.  
- **Рекомендация:** Договор/акт ЦОД с адресом в РК; то же для backup/S3/логов; запрет зарубежного object storage для ПДн без оснований ст. 16.

### KZ-08 — Нет процедуры уведомления о нарушении безопасности ПДн

- **Критичность:** High · **Статус:** Подтверждено (отсутствие документов/runbooks)  
- **Норма:** Приказ 481/НҚ; 94-V (уведомление уполномоченного органа).  
- **Рекомендация:** Playbook: обнаружение → оценка → уведомление за 1 раб. день → фиксация доказательств.

### KZ-09 — Приём реквизитов карты в приложении

- **Критичность:** High · **Статус:** Подтверждено  
- **Компонент:** `SubscriptionController::purchase` валидирует `card_number`, `card_expiry`, `card_cvc`; в БД уходит last4. View `subscription/checkout.blade.php`.  
- **Риск:** PAN/CVC в POST, возможны логи/дампы памяти; не PCI SAQ-совместимый ввод.  
- **Рекомендация:** Только платёжный виджет эквайера (Kaspi и т.п.); не принимать CVC/PAN на своём origin.

### KZ-10 / KZ-24 — Временные пароли поставщиков

- **Критичность:** High · **Статус:** Подтверждено  
- **Компонент:** `Supplier` Crypt::encryptString; moderator show расшифровывает; в миграции также `temporary_password` plaintext-колонка.  
- **Риск:** Компрометация APP_KEY = массовое раскрытие; доступ модератора к паролям в открытом виде.  
- **Рекомендация:** Одноразовые invite-ссылки; запрет хранения восстанавливаемого пароля; удалить plaintext-колонку.

### KZ-11 — Файлы в публичном диске

- **Критичность:** Medium · **Компонент:** `PublicFileStorage::store(..., 'public')`  
- **Риск:** Угадывание/утечка URL; документы клиентов в web-accessible storage.  
- **Рекомендация:** private disk + authorized download / temporary signed URLs; запрет исполняемых типов; проверка содержимого.

### KZ-12 — Сессии

- **Критичность:** Medium · **Доказательство:** `SESSION_ENCRYPT=false`; `SESSION_SECURE_COOKIE` не задан в `.env` → Secure зависит от окружения.  
- **Рекомендация:** Encrypt sessions; Secure=true на HTTPS; SameSite=lax/strict; короткий lifetime для админов.

### KZ-13 — CDN за рубежом

- **Критичность:** Medium (условное юридическое) · **Доказательство:** bunny.net, jsdelivr, unpkg в layouts.  
- **Рекомендация:** Self-host assets; при необходимости — согласие на трансграничную передачу техданных / оценка ст. 16.

Остальные ID (KZ-14…KZ-22) — см. матрицу; детали аналогичны: soft delete без политики уничтожения, AWS us-east-1 default, отсутствие MFA, риск логов при DEBUG, избыточные поля поставщика (ИНН+полный банк.пакет без отдельного согласия/цели).

## Раздел 10. План устранения

### Критические меры (24 часа)
1. Запрет вывода в production с реальными ПДн до consent + политики.  
2. Отключить приём PAN/CVC на своём домене.  
3. Зафиксировать/подтвердить размещение БД в РК или остановить сбор.  
4. Ограничить доступ к `.env` / APP_KEY; сменить слабые секреты локальной почты.

### До production (обязательно)
1. Согласие + журнал версий; политика с БИН оператора.  
2. Приказ о ответственном; контакты.  
3. Audit log действий с ПДн.  
4. Шифрование/минимизация ИНН/банка; убрать восстанавливаемые пароли.  
5. Private file storage + ACL.  
6. Права субъекта (export/erase).  
7. SESSION_ENCRYPT + Secure cookies; APP_DEBUG=false; APP_ENV=production.  
8. Self-host CDN assets или правовое оформление.  
9. Playbook уведомления 481/НҚ.  
10. Подтверждение backup в РК + шифрование backup + тест restore.

### 30 дней
- MFA для system_admin; periodic access review; DPIA/перечень необходимых ПДн; договоры с процессорами; обучение; централизованный мониторинг инцидентов.

### Планово
- Сертифицированное СКЗИ / юр. заключение по 179/НҚ; pen-test; dependency CVE monitoring; immutable backups.

## Приложение A. Положительные наблюдения

- `.env` в `.gitignore`; `APP_KEY` не в tracked files.  
- Rate limiting на login/register/password-email/api-business.  
- Policies для Project, Client, SupplierOrder.

- Недавние фиксы IDOR/path traversal (по истории проекта) снижают техриск, но **не заменяют** юридическое соответствие.

## Приложение B. Ограничение ответственности

Аудит выполнен по доступной кодовой базе и локальной среде. Выводы о production-инфраструктуре требуют отдельного доступа к ЦОД, договорам хостинга и серверным конфигам. Классификация отдельных полей как «персональные данные ограниченного доступа» может потребовать юридического заключения; технические факты хранения и отсутствия согласия при этом остаются подтверждёнными.
